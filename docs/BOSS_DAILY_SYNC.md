# 公司招聘日报

经 2026-09-09 Chrome 现场验证：`/web/chat/index` 顶部“招聘数据”展开“我的数据 / 公司数据”，点击“公司数据”新开 `/web/frame/enterprise/recruit/data`。页面导航“招聘数据”，默认“近七天”，下拉可选“按天查看”。日期控件 placeholder 为“选择日期”。页面当前登录身份位于“使用说明”之前。日报采用标准 table/th/td，表头包含图标私用区字符；空个人资料单元格存在，不能从纯文字顺序推算指标列。

仅采集管理员配置的来源账号（本次是成珈莉）可见的公司报表。BOSS姓名是行主体，来源账号是采集权限，两者不能混淆。普通设备必须当前分配给来源账号；已有公司管理员设备也可采集公司报表，且不改变候选人账号分配。

目标为现有“招聘者每日数据”子表。仅写入日期、BOSS姓名、BOSS查看牛人、BOSS发起聊天、BOSS沟通、牛人查看BOSS、牛人发起聊天。手机号、邮箱、职务、公司、聊天内容和完整HTML均不上报。日报不使用候选人表的字段修复函数。

扩展通过持久 Chrome alarms 在北京时间零点后采集前一天。浏览器关闭时无法打开 BOSS；重启、登录或每五分钟检查时补采。最多自动追补过去31天，单批最多7天；成功后当天不再自动重复采集，手动“检查并同步日报”可纠正昨天的延迟统计，按日期与BOSS姓名覆盖更新。后台无对应招聘账号的报表人员也能入表，不自动创建账号绑定。

扩展“公司日报管理员登录”仅接受本公司已有 ACTIVE ADMIN 飞书身份，不创建或替换 BOSS 分配。此入口授权设备，与普通“绑定飞书账号”的候选人归属绑定分开。保留原有管理员自己的候选人访问权限，非本人分配的候选人采集仍由原接口拒绝。

日期必须点击真实日历控件：实测直接改 input 的 value 不会更新 BOSS 查询。按可见年月切换月份，在星期一到星期日的日历表格中验证连续日期，再点击本月目标单元格；下一月的同号日期不能混选。提交前再次验证日期输入与报表统计日期一致。

后台只打开自己创建的隐藏企业数据标签，确认来源身份、按天日期、数据更新时间后读取所有分页，再原子提交整日。缺字段、缺数字、分页停滞、同名歧义、登录失效均失败重试，不把未知当零。任务结束只关闭自己的标签。

数据先入专用日报队列，候选人同步worker同时处理日报，飞书按日期+BOSS姓名幂等更新。网络失败指数退避5次，失败状态只存错误类型；重采可重新排队。旧版单人日报接口在生产返回410要求升级。
