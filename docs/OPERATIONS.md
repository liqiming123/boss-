# 开发运维后台

运维后台用于开发和系统管理员排查扩展、飞书同步与补扫问题，不面向普通招聘者。无域名测试阶段，本机页面为 `http://localhost:5173`，API 经 SSH 隧道访问 `http://localhost:8000/api/v1`。

## 登录

管理后台只提供“使用飞书登录”。飞书 OAuth 回调核对 `open_id` 及 `ADMIN` / `HR_MANAGER` 权限后，服务器写入 `HttpOnly` 会话 Cookie。前端不保存、不显示、不刷新 access token 或 refresh token，也不提供邮箱密码登录。

会话 Cookie 无法被页面 JavaScript 读取，退出时由服务器删除。正式域名上线后 Cookie 必须只通过 HTTPS 发送。

## 总览检测项

- API 与数据库：后台能成功加载即证明 API 鉴权及数据库查询可用。
- Worker 心跳：候选人同步、飞书通知、数据清理各占数据库一行，每30秒更新；超过90秒视为失联。
- 飞书同步队列：展示等待、处理中、失败、成功数量；失败任务可以重新入队。
- 点击查重提醒：展示当前查看者、命中招聘者、证据等级、24 小时冷却命中次数、最近检测和最近发送时间。
- 聊天快照：展示完成、未采集、失败数量。数据库只保存附件令牌和状态。
- 隔夜补扫：按 BOSS 招聘账号展示最后成功水位；已有候选人却无水位会告警。
- 自动补扫开关保存在每台扩展设备本地，默认开启；关闭不会清除服务端水位，重新开启后继续。
- 飞书与扩展绑定：展示 BOSS账号、飞书显示名、活跃设备、最近活动和已同步候选人数。
- 扩展设备：管理员可撤销，撤销后对应扩展访问令牌立即失效。
- 扩展诊断：只展示版本、页面类型、字段提取状态、错误码和脱敏上下文。

## 告警等级

- 严重：Worker 无心跳/报错、同步任务达到重试上限、通知发送失败。
- 警告：队列有积压、快照缺失、已有业务数据但没有补扫水位。
- 正常：所有 Worker 心跳新鲜，队列无失败，快照和补扫状态完整。

总览每15秒自动刷新。systemd 的“active”只表示进程存在，Worker 心跳用于发现反复崩溃或代码未实际进入处理循环的情况。

## 备份和日常排查

- 每日使用 `pg_dump --format=custom` 备份，并加密存储、定期恢复验证。
- 岗位待映射时由管理员处理，禁止系统擅自创建内部岗位。
- BOSS 页面改版时冻结对应 adapter，采集脱敏诊断，更新 fixture 和版本后再发布。
- 不要求招聘者上传完整页面、Cookie、Token 或简历；诊断只接受脱敏结构。

## 本地启动

```bash
ssh -N -L 127.0.0.1:8000:127.0.0.1:18082 databoard-server
npm --prefix apps/web run dev -- --host 127.0.0.1
```

正式域名上线时将编译后的 `apps/web/dist` 交给 Nginx，并把 `VITE_API_BASE_URL` 构建为正式 HTTPS API 地址。
